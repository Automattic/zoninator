# Filters and actions

Reference for the hooks Zoninator exposes. Generated by reading the source — if you find something out of date, grep for `apply_filters` and `do_action` in `src/` and please open a PR.

File paths are relative to the plugin root. All hooks fire from `src/class-zoninator.php` unless noted otherwise.

## Initialisation

### `zoninator_pre_init` (action)

Fires at the start of the main plugin's `init()` method, before the taxonomy is registered or any default post-type support is added.

### `zoninator_post_init` (action)

Fires at the end of `init()`, after the taxonomy is registered and all default `admin_*` hooks have been wired up. Use this to attach late behaviour that depends on the plugin being fully booted.

## Configuration

### `zoninator_zone_lock_period` (filter)

How long a zone lock is held without activity, in seconds. Defaults to `30`.

- **Parameters:** `int $seconds`

### `zoninator_zone_max_lock_period` (filter)

Maximum total time a user can hold a lock, in seconds. Defaults to `600`. Return `-1` (or use `z_disable_zoninator_locks`) to disable locking entirely.

- **Parameters:** `int $seconds`

### `zoninator_posts_per_page` (filter)

Number of posts shown per page in the admin search and recent-posts dropdown. Defaults to `10`.

- **Parameters:** `int $count`

## Capabilities

By default all three capability hooks return `edit_others_posts`.

### `zoninator_add_zone_cap` (filter)

Capability required to create a new zone.

- **Parameters:** `string $capability`

### `zoninator_edit_zone_cap` (filter)

Capability required to edit an existing zone.

- **Parameters:** `string $capability`

### `zoninator_manage_zone_cap` (filter)

Capability required to manage the Zones admin screen as a whole.

- **Parameters:** `string $capability`

### `zoninator_current_user_can_edit_zone` (filter)

Per-zone editing check, run after the user has cleared the global `zoninator_edit_zone_cap`. Use this to lock down individual zones.

- **Parameters:** `bool $has_cap`, `int $zone_id`

## REST API permissions

### `zoninator_rest_get_zones_permissions_check` (filter)

Fires from `src/class-zoninator-api-controller.php`. Whether the `GET /zoninator/v1/zones` endpoint authorises the current request. Defaults to `is_user_logged_in()` since 0.11.0; return `true` to restore the historical anonymous behaviour.

- **Parameters:** `bool $authorised`, `WP_REST_Request $request`

```php
add_filter( 'zoninator_rest_get_zones_permissions_check', '__return_true' );
```

## Admin UI

### `zoninator_admin_page_get_zones_args` (filter)

Arguments passed to `get_zones()` when rendering the admin Zones list page.

- **Parameters:** `array $args`

### `zoninator_zone_post_columns` (filter)

Columns rendered for each post inside the zone editor. Two call sites — one for HTML output, one for the array consumed by the JS UI.

- **Parameters:** `array $columns`, `WP_Post $post`, `WP_Term $zone`

### `zoninator_pre_zone_fields` / `zoninator_post_zone_fields` (actions)

Wrap the zone-edit form fields. Use these to add custom inputs that you persist via `zoninator_insert_zone` / `zoninator_update_zone`.

- **Parameters:** `WP_Term $zone`

### `zoninator_pre_zone_readonly` / `zoninator_post_zone_readonly` (actions)

Same shape as the field hooks above, but fire when rendering the zone in read-only mode (e.g. when a different user has it locked).

- **Parameters:** `WP_Term $zone`

### `zoninator_advanced_search_fields` (action)

Fires inside the advanced search panel of the post picker. Zoninator itself attaches the category and date filters to this hook — add your own to extend the panel.

### `zoninator_advanced_filter_category` (filter)

`wp_dropdown_categories()` arguments for the category filter inside advanced search.

- **Parameters:** `array $args`

### `zoninator_advanced_filter_date` (filter)

The list of date-filter options. Defaults to `[ 'all', 'today', 'yesterday' ]`. Strings are passed through `strtotime()`; arrays use `value`/`label` keys.

- **Parameters:** `array $dates`

### `zoninator_advanced_filter_date_default` (filter)

Default selected date filter.

- **Parameters:** `string $default`

## Post search and recent-posts dropdown

### `zoninator_recent_posts_args` (filter)

`WP_Query` args used to populate the "recent posts" dropdown in the zone editor. Two call sites (the AJAX handler and the initial render).

- **Parameters:** `array $args`

### `zoninator_search_args` (filter)

`WP_Query` args used by the AJAX post search.

- **Parameters:** `array $args`

### `zoninator_search_results_post` (filter)

Each search result is passed through this filter before being JSON-encoded.

- **Parameters:** `array $result`, `WP_Post $post`

## Zone CRUD

### `zoninator_insert_zone` (filter)

Arguments passed to `wp_insert_term()` when a new zone is created.

- **Parameters:** `array $args`

### `zoninator_update_zone` (filter)

Arguments passed to `wp_update_term()` when an existing zone is updated.

- **Parameters:** `array $args`, `int $zone_id`, `WP_Term $zone`

### `zoninator_delete_zone` (action)

Fires after a zone has been deleted.

- **Parameters:** `int $zone_id`

### `zoninator_add_zone_posts` (action)

Fires after one or more posts have been added to a zone.

- **Parameters:** `WP_Post[] $posts`, `WP_Term $zone`

### `zoninator_remove_zone_posts` (action)

Fires after one or more posts have been removed from a zone.

- **Parameters:** `WP_Post[] $posts`, `WP_Term $zone`

## Term splitting (WordPress 4.2 carry-over)

### `zoninator_split_shared_term` (action)

Fires before Zoninator copies posts from `$old_term_id` to `$new_term_id` after a WordPress shared-term split.

- **Parameters:** `int $old_term_id`, `int $new_term_id`, `int $term_taxonomy_id`

### `zoninator_did_split_shared_term` (action)

Fires after the copy is complete.

- **Parameters:** `int $old_term_id`, `int $new_term_id`, `int $term_taxonomy_id`

## JSON feed at `/zones/{slug}/feed.json`

### `zoninator_zone_feed_fields` (filter)

Fields included in each post in the JSON feed. Defaults to `[ 'ID', 'post_date', 'post_title', 'post_content', 'post_excerpt', 'post_status', 'guid' ]`.

- **Parameters:** `string[] $fields`

### `zoninator_json_feed_fields` (filter)

Args passed to `get_zone_posts()` when assembling the feed. Use this to constrain which posts appear (e.g. limit count, restrict post types).

- **Parameters:** `array $args`, `int|string $zone_slug_or_id`

### `zoninator_json_feed_results` (filter)

Final feed payload before encoding to JSON.

- **Parameters:** `array $results`, `int|string $zone_slug_or_id`

## Widget

### `zone_posts_widget_block_save_cache_seconds` (filter)

Fires from `src/class-zoninator-zoneposts-widget.php`. How long (in seconds) the widget cache is locked against re-population after a flush. Defaults to `5`. Set to `0` to disable the lock.

- **Parameters:** `int $seconds`

> **Naming note.** This hook predates the `zoninator_` prefix convention and cannot be renamed without breaking sites that use it.

## REST framework hooks

The vendored Mixtape REST framework in `src/zoninator_rest/` exposes a few internal hooks under the `mt_*` and `mixtape_*` prefixes. These are framework-level extension points rather than parts of Zoninator's public API and are unlikely to be useful from outside the plugin. They are listed here for completeness:

- `mt_environment_before_start`, `mt_environment_after_start`, `mt_environment_get_rest_apis`, `mt_variable_get`
- `mixtape_rest_api_schema_properties`, `mixtape_type_registry_get_types`, `mixtape_data_store_*`
- `rest_api_schema_properties` (called from Zoninator's schema converter)
