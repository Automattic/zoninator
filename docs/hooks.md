# Filters and actions

Reference for the hooks Zoninator exposes. Generated by reading the source — if you find something out of date, grep for `apply_filters` and `do_action` in `src/` and please open a PR.

File paths are relative to the plugin root. Each section says which file its hooks fire from.

To unhook one of Zoninator's own callbacks from a core hook, such as the JSON feed on `template_redirect`, see [Unhooking Zoninator's callbacks](php-api.md#unhooking-zoninators-callbacks), which lists every one.

## Configuration

These fire from `src/Infrastructure/WordPress/Settings.php` each time Zoninator reads the value, so a filter added at any point before then counts.

### `zoninator_zone_lock_period` (filter)

How long a zone lock lasts unless it's renewed, in seconds. The Zones screen renews it this often. Defaults to `30`.

- **Parameters:** `int $seconds`

### `zoninator_zone_max_lock_period` (filter)

How long, in seconds, the Zones screen keeps a zone locked while the user doesn't reorder, add or remove its posts. Defaults to `600`. After that, the screen asks whether they're still working, and goes to the Dashboard if not. Return `-1`, or use `zoninator_disable_locks`, so the Zones screen doesn't lock zones.

- **Parameters:** `int $seconds`

### `zoninator_posts_per_page` (filter)

Number of posts the post search offers, on the Zones screen, through `GET /zoninator/v1/search` when no `limit` is given, and through the `zoninator/search-posts` ability. It's also the number of latest posts offered before anything is typed. Defaults to `10`.

- **Parameters:** `int $count`

### `zoninator_post_count_limit` (filter)

The most posts a zone may hold: 100 by default. Return `0` for no limit.

- **Parameters:** `int $limit`, `int $zone_id`

```php
// The homepage zone holds five posts; other zones keep the default.
add_filter( 'zoninator_post_count_limit', function ( $limit, $zone_id ) {
	$homepage = zoninator_get_zone( 'homepage' );

	return $homepage && $homepage->term_id === $zone_id ? 5 : $limit;
}, 10, 2 );
```

A change that would take a zone past its limit is refused, on the Zones screen, over the REST API (`400`, `zone-full`) and through the abilities, and the zone is left as it was. A zone that already holds more than its limit keeps its posts, and can still be reordered or trimmed, but takes no more until it's back under.

## Capabilities

These fire from `src/Infrastructure/WordPress/Capabilities.php`. By default all three capability hooks return `edit_others_posts`.

### `zoninator_add_zone_cap` (filter)

Capability required to create a new zone.

- **Parameters:** `string $capability`

### `zoninator_edit_zone_cap` (filter)

Capability required to edit an existing zone's name and description, or delete it.

- **Parameters:** `string $capability`

### `zoninator_manage_zone_cap` (filter)

Capability required to open the Zones screen and curate a zone: add, remove and reorder its posts, search for posts, and take its lock. The REST routes for these check it too.

- **Parameters:** `string $capability`

### `zoninator_current_user_can_edit_zone` (filter)

Per-zone editing check. `$has_cap` is whether the user has the `zoninator_edit_zone_cap` capability, and the filter runs whatever its value, so returning `true` lets a user without the capability rename or delete the zone. Use this to stop some users renaming or deleting individual zones, and return `$has_cap` for zones you don't mean to change. It doesn't stop them curating a zone's posts, which `zoninator_manage_zone_cap` governs.

- **Parameters:** `bool $has_cap`, `int $zone_id`, `int $user_id`

`$user_id` is the user being asked about. Use it in place of `get_current_user_id()`: despite the filter's name, code can change a zone for a user who isn't the one logged in, through `GuardedZoneManager`.

## REST API permissions

### `zoninator_rest_get_zones_permissions_check` (filter)

Fires from `src/Infrastructure/WordPress/Rest/Permissions.php`. Whether the `GET /zoninator/v1/zones` endpoint authorizes the current request. Defaults to whether the user can edit posts (`edit_posts`), which the block editor's zone picker needs, or curate zones. Before 1.0.0 it was whether they were logged in. Return `true` to let anyone list the zones. A refused request gets core's `rest_forbidden` error.

- **Parameters:** `bool $authorized`, `WP_REST_Request $request`

```php
add_filter( 'zoninator_rest_get_zones_permissions_check', '__return_true' );
```

## Admin UI

These fire from the classes under `src/Infrastructure/WordPress/Admin/`, which print the Zones screen.

### `zoninator_admin_page_get_zones_args` (filter)

`get_terms()` arguments for the list of zones on the Zones screen. `taxonomy` is always the zone taxonomy. It doesn't change `zoninator_get_zones()`, the REST API or the abilities.

- **Parameters:** `array $args`

### `zoninator_zone_post_columns` (filter)

Columns shown for each post in a zone on the Zones screen: column key => callback, which receives `$post` and `$zone` and prints the cell. Fires from `src/Infrastructure/WordPress/Admin/ZonePostRow.php`, for each row the Zones screen prints, and for the row it fetches after a post is added. It doesn't fire for a post the current user may not read: that row keeps its place in the zone, says only that the user has no access to the item, and has a Remove button.

- **Parameters:** `array $columns`, `WP_Post $post`, `WP_Term $zone`

### `zoninator_pre_zone_fields` / `zoninator_post_zone_fields` (actions)

Wrap the zone form's fields. Use these to add your own inputs, and register each one as a detail with `zoninator_zone_detail_defaults`. The form saves only the name, slug and description, so save your value yourself: in `zoninator_insert_zone` and `zoninator_update_zone`, `$args['description']` holds the zone's details as a serialized array.

- **Parameters:** `WP_Term|array $zone`: the zone, or an empty array on the form for a new zone

### `zoninator_pre_zone_readonly` / `zoninator_post_zone_readonly` (actions)

Same shape as the field hooks above, but fire when the zone is shown read-only: when another user has it locked, or the user can't edit it.

- **Parameters:** `WP_Term|array $zone`

### `zoninator_advanced_search_fields` (action)

Fires inside the advanced search panel of the post picker. Zoninator itself attaches the category and date filters to this hook — add your own to extend the panel.

### `zoninator_advanced_filter_category` (filter)

`wp_dropdown_categories()` arguments for the category filter inside advanced search.

- **Parameters:** `array $args`

### `zoninator_advanced_filter_date` (filter)

The list of date-filter options. Defaults to `[ 'all', 'today', 'yesterday' ]`. Strings are passed through `strtotime()`; arrays use `value`/`label` keys, and a `value` must be a `Y-m-d` date, or the search ignores it.

- **Parameters:** `array $dates`

### `zoninator_advanced_filter_date_default` (filter)

Default selected date filter: one of the options' values, a `Y-m-d` date, or `''` for all dates.

- **Parameters:** `string $default`

## Content search

These fire from `src/Infrastructure/WordPress/Search.php`, for the `GET /zoninator/v1/search` route and the `zoninator/search-posts` ability alike.

### `zoninator_recent_posts_args` (filter)

`WP_Query` args for the latest content, which the Zones screen's "Add content" field offers before anything is typed.

- **Parameters:** `array $args`, `int $zone_id` (the zone being edited, or `0`)

### `zoninator_search_args` (filter)

`WP_Query` args used by the post search once something is typed. When the term is a post ID, the search looks that post up with these args, minus `s`, so the lookup only finds a post the text search could offer.

- **Parameters:** `array $args`, `int $zone_id` (the zone being edited, or `0`)

Use `$zone_id` to focus the search on what suits a zone, for example only posts in a matching category:

```php
add_filter( 'zoninator_search_args', function ( $args, $zone_id ) {
	$sport_zone = zoninator_get_zone( 'sport' );
	if ( $sport_zone && $zone_id === $sport_zone->term_id ) {
		$args['category_name'] = 'sport';
	}
	return $args;
}, 10, 2 );
```

### `zoninator_search_results_post` (filter)

Each search result, including the latest content offered before anything is typed and a post found by its ID, is passed through this filter before being JSON-encoded. The result has `title`, `post_id`, `date`, `post_type`, `post_type_label`, `post_status` and `post_status_label`; the editor shows the labels when they're present.

- **Parameters:** `array $result`, `WP_Post $post`

## Zone CRUD

These fire from `src/Infrastructure/WordPress/TermZoneRepository.php`, for zones, and `src/Infrastructure/WordPress/PostMetaZonePostsRepository.php`, for the posts in them. The one exception is `zoninator_zone_detail_defaults`, which fires from `src/Infrastructure/WordPress/Settings.php`.

### `zoninator_insert_zone` (filter)

Arguments passed to `wp_insert_term()` when a new zone is created: its `slug`, and its details, serialized, as `description`. The name is passed to `wp_insert_term()` separately.

- **Parameters:** `array $args`

### `zoninator_zone_detail_defaults` (filter)

The details a zone stores in its term, with their default values. Zoninator saves only `description`. Add your own detail here, then read it as a property of the zone, for example `zoninator_get_zone( 'homepage' )->kicker`. Zones without it get the default, and updating a zone without sending it keeps its current value.

- **Parameters:** `array $defaults` (detail name => default value)

```php
add_filter( 'zoninator_zone_detail_defaults', function ( $defaults ) {
	return $defaults + [ 'kicker' => '' ];
} );
```

### `zoninator_update_zone` (filter)

Arguments passed to `wp_update_term()` when an existing zone is updated.

- **Parameters:** `array $args`, `int $zone_id`, `WP_Term $zone`

### `zoninator_delete_zone` (action)

Fires after a zone has been deleted.

- **Parameters:** `int $zone_id`

### `zoninator_add_zone_posts` (action)

Fires after one or more posts have been added to a zone.

- **Parameters:** `int[] $post_ids`, `WP_Term $zone`

`$post_ids` is always an array of post IDs, however the posts were added.

Replacing the zone's posts, rather than appending, fires `zoninator_remove_zone_posts` with every post that was in the zone, then this with every post now in it. Only the posts that leave the zone or change place are written, so while `zoninator_remove_zone_posts` runs, the posts staying in the zone still have their places.

When posts are appended, `$post_ids` holds only the ones that weren't in the zone already, as those keep their place. If none were new, the action doesn't fire.

### `zoninator_remove_zone_posts` (action)

Fires after one or more posts have been removed from a zone.

- **Parameters:** `int[] $post_ids`, `WP_Term $zone`

`$post_ids` is always an array of post IDs: the posts asked to be removed, whether or not they were in the zone. When the whole zone is cleared (replacing its posts or deleting the zone), it's every post that was in the zone, whatever its status, and the array is empty if the zone had none.

## JSON feed

These fire from `src/Infrastructure/WordPress/Feed.php`, for the JSON feed at `/zones/{slug}/feed.json` and the `GET /zoninator/v1/zones/{zone_id}/posts` REST route alike. `$zone_slug_or_id` is the slug from the feed's URL, or the ID from the REST route.

### `zoninator_zone_feed_fields` (filter)

Fields included in each post in the JSON feed. Defaults to `[ 'ID', 'post_date', 'post_title', 'post_excerpt', 'post_status', 'guid' ]`.

The feed is public, and gives each field as it's stored. Before 1.0.0 the defaults included `post_content`. Stored content hasn't been through the site's content filters, so a paywall or membership plugin that holds content back there doesn't apply to it. Add it back only if all of a zone's content is public:

```php
add_filter(
	'zoninator_zone_feed_fields',
	static function ( $fields ) {
		$fields[] = 'post_content';

		return $fields;
	}
);
```

A password-protected post's content and excerpt are always empty.

- **Parameters:** `string[] $fields`

### `zoninator_json_feed_fields` (filter)

`WP_Query` arguments for the feed's posts, merged over the zone query's defaults, as `zoninator_get_posts_in_zone()` takes them. Despite the name, they're query arguments, not fields. Use this to limit which posts appear, such as how many, or which post types. `orderby` and `meta_key` can't be changed.

- **Parameters:** `array $args`, `int|string $zone_slug_or_id`

### `zoninator_json_feed_results` (filter)

Final feed payload before encoding to JSON. Return a `WP_Error` to refuse it: the feed then sends `406` with a body of `null`, and the REST route `400` with the code `zone-feed-error`.

- **Parameters:** `array $results`, `int|string $zone_slug_or_id`

## Widget

### `zoninator_zone_posts_widget_html` (filter)

Fires from `src/Infrastructure/WordPress/ZonePostsWidget.php`. Replaces the HTML for the posts in a Zone Posts widget, so a theme can show them its own way, such as with thumbnails or excerpts. Return `false` (the default) to keep the list of links. The widget title, description and wrapper still come from the widget, and the HTML passes through `wp_kses_post()`.

The callback runs on every page view that shows the widget, so cache the result yourself if it's costly to build.

- **Parameters:** `string|false $html`, `WP_Post[] $posts` (the zone's posts, in order), `WP_Query $query` (the zone query that found them)

```php
add_filter( 'zoninator_zone_posts_widget_html', function ( $html, $posts ) {
	$items = array_map(
		fn( $post ) => sprintf( '<li>%s <a href="%s">%s</a></li>', get_the_post_thumbnail( $post, 'thumbnail' ), esc_url( get_permalink( $post ) ), esc_html( get_the_title( $post ) ) ),
		$posts
	);
	return '<ul class="zone-thumbs">' . implode( '', $items ) . '</ul>';
}, 10, 2 );
```
